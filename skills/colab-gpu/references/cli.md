# `orca-colab` CLI Reference

Invoke via `orca-colab <cmd> --json` or `npx -y https://codeload.github.com/vzxxbacq/orca-colab/tar.gz/2944ee151e7ef2d08a5598c00c6cce4e3109f13c <cmd> --json`.
With `--json`, stdout carries exactly one JSON object and all progress/errors go to stderr with the `[colab]` prefix.

| Command | Description | Exit codes |
|---|---|---|
| `doctor [--json]` | Check Node ≥ 20, `git`, `tar` and the Google sign-in (`checks.oauth`); `policy` holds the guardrails that apply in the current directory, with `policy.source` `"project"` (and `policy.file`) or `"machine"`; a broken project file fails `checks.guardrails`; `mode` is `"direct-api"` once signed in. | `0` all required checks pass, `1` something missing (`actions[]`) |
| `auth [login \| add \| list \| switch \| status \| logout \| redirect <url>] [--account A] [--add] [--all] [--no-browser] [--json]` | Manage one or multiple Google OAuth accounts (`login --add` to add another Google account, `list` to view all accounts & balances, `switch <account>` to change default). On a headless server use `login --no-browser`, open the printed URL anywhere, then paste the `http://127.0.0.1:…` URL it redirects to into `auth redirect <url>` on the server. | `0` ok, `1` error |
| `up [--name N] [--account A] [--gpu T4\|L4\|A100\|CPU] [--high-ram] [--new] [--keep] [--json]` | Guardrails come from the project's `.orca/colab.json` (see below) over the machine config. Provision or reuse a Colab runtime through `colaboratory.googleapis.com/v1beta/runtimes`, query the GPU over `/colab/tty`, write the session and return session JSON with `estimatedCuPerHour`. Refuses to start a new runtime (`step: "policy"`) outside the allowed GPUs or beyond the runtime cap, and (`step: "budget"`, `code: "BUDGET_REACHED"`, with `budgetCu` and `estimatedMonthlyUsedCu`) once the estimated use this month has reached the monthly budget; reusing a running session is not refused. | `0` ready, `1` not signed in / policy / budget / provisioning error (`step`), `3` aborted |
| `status [--local] [--json]` / `ls [--json]` | List the runtimes of the signed-in Google account, asked from Colab on every call (`--local` skips the call), including ones started from other machines: `startedHere` is false for those and `origin` names the machine and agent (`null` = unknown origin: no orca-colab record on the runtime). Each has `reachable` (has a live runtime proxy and is not a zombie) and `ageSeconds`. `forwards` lists the session's active port forwards (`listen`, `remotePort`, `pid`). `recentlyEnded` lists sessions that ended in the last 24 hours with `endedAt`, `cause` (`user`, `idle-watchdog`, `colab-died`) and `reason`. The runtime proxy token is never printed. | `0` |
| `run [--session N] [--cwd DIR] [--env KEY=VAL] [--detach NAME \| --attach NAME] [--json] -- <cmd…>` | Execute `<cmd…>` on the runtime as a job that is followed until it ends: it runs detached there with its record and output under `/content/orca/.orca-colab/tasks/`, so other machines see it too; Ctrl-C stops it (`--cwd` defaults to session `remoteRoot`; `run -- bash -l` from a terminal opens an interactive shell). | Propagates remote exit code |
| `job submit [--session N] [--name TITLE] [--cwd DIR] [--env KEY=VAL] [--sync] [--wait] [--json] -- <cmd…>` | Submit an algorithm/compute task to the GPU session. It runs detached on the runtime with its record and complete output in `/content/orca/.orca-colab/tasks/<id>.json` / `.log` (it survives this machine going away); a local copy is kept in `~/.orca-colab/tasks/`. | `0` (or remote exit code with `--wait`) |
| `job ls [--session N] [--status S] [--json]` | List GPU tasks, including ones submitted from other machines (read from the runtimes; `origin` names who), with status (`running`, `succeeded`, `failed`, `stopped`), exit code, and session. | `0` |
| `job logs <id> [--tail N=200] [--follow] [--json]` | Read or follow live stdout/stderr output for task `<id>`, whichever machine submitted it. | `0` ok, `1` error |
| `job stop <id> [--json]` | Terminate a running task on the remote Colab GPU (from any machine) and mark it `stopped`. | `0` ok, `1` error |
| `sync [--session N] [--to DIR] [path=.] [--json]` | Pack the workspace with local `tar` (honoring `.gitignore` and `.colabignore`, excluding `.git/`) and unpack it at `/content/orca/<basename>` over `/colab/tty`; updates `remoteRoot`. | `0` ok, `1` error |
| `pull [--session N] <remotePath> <localDir> [--json]` | Pack `<remotePath>` (file or directory, relative to `remoteRoot` unless absolute) into a tar.gz on the runtime, download it over HTTPS from the runtime's Jupyter `/files` endpoint and unpack it into `<localDir>/<basename>`. Binary-safe. | `0` ok, `1` error |
| `down [--session N \| --all] [--force] [--json]` | Call `DELETE /v1beta/runtimes/<id>`, record `session.end` in the ledger and delete the session file; if the API refuses, mark `state: "zombie"` (`reason: "api-delete-failed"`). A runtime another machine is using right now (a running job or command, per the records on the runtime) is left alone with `reason: "in-use-elsewhere"` and `inUseBy`, and so is one whose records could not be read (`reason: "use-unknown"`); `--force` releases it anyway. Without `--session`, a runtime started on this machine is preferred. | `0` released (or already gone), `1` in use elsewhere or unknown, `4` zombie |
| `credits [--account A] [--json]` | Show approximate balance (`estimatedBalanceCu`), burn rate (`estimatedBurnCuPerHour`), `estimatedHoursRemaining`, and monthly budget usage from the ledger; `projectBudget` (`budgetCu`, `estimatedMonthlyUsedCu`, `estimatedBudgetUsedPercent`, `file`) when the project in the current directory sets its own budget. | `0` |
| `credits calibrate [--browser] [--account A] [--json]` | Sync balance from `colab.research.google.com/tun/m/ccu-info` (via OAuth) or Orca's browser (`--browser`). | `0` ok, `1` error |
| `credits set <cu> [--account A] [--json]` | Record a manual balance calibration event (`calibrate`) from Colab's Resources pane. | `0` ok, `1` error |
| `credits budget <cu> [--account A] [--json]` | Record a monthly compute-unit budget (`budget.set`) for the account. It is the machine's budget and a hard limit for `up` in projects without their own `monthlyBudgetCu`; `0` removes it. | `0` ok, `1` error |
| `ledger [--month YYYY-MM] [--account A] [--json]` | List raw credit ledger events (`session.start`, `session.end`, `calibrate`, `budget.set`). | `0` |
| `forward --port P [--session N] [--listen HOST:PORT] [--timeout S=300] [--json]` | Listen on this machine (`127.0.0.1:P` by default; port `0` picks a free one) and forward every HTTP request to port `P` on the runtime through its Jupyter server; method, path, query, headers, body, status and response headers pass through unchanged. Runs until interrupted; with `--json` prints `{ ok, session, remotePort, listen, url, pid }` once it listens. About 0.5 s per request on top; no WebSockets or streaming; bodies up to 256 MB. Its own errors are JSON: `502 session_gone`, `502 port_unreachable`, `504 forward_timeout`. `status` lists it under `forwards`. | `0` when stopped, `1` error |
| `rates [--set KEY=CU_PER_HOUR] [--json]` | View or override approximate per-hour compute-unit rates (`T4`, `L4`, `A100`, `TPU v2-8`, `CPU`, `unknown`). | `0` ok, `1` error |
| `mcp` | Serve every command above as MCP tools on stdio (`doctor`, `auth_login`, `auth_wait`, `up`, `sync`, `run`, `job_submit`, `job_wait`, `job_logs`, `pull`, `down`, `credits`, …) for `orca bot tools add`, Claude Code, Codex and other MCP clients. stdout carries JSON-RPC only. | `0` when stdin closes |

## Guardrails file: `<project>/.orca/colab.json`

Found by walking up from the current directory (MCP: from `workspace_path`); the nearest file wins. Every
field is optional and overrides the machine's `~/.orca-colab/config.json`; without a file the machine config
applies alone. Whole-line `//` comments are allowed. A file that cannot be parsed or holds a bad value fails
`up` and `doctor`.

| Field | Meaning |
|---|---|
| `allowedGpus` | GPU tiers that may be started from this project: `T4`, `L4`, `A100`, `G4`, `H100`, `CPU`. |
| `maxConcurrentSessions` | Runtimes started from this project that may run at once (whole number ≥ 1). |
| `monthlyBudgetCu` | Hard limit on the project's estimated compute units per month, counted from the ledger of the machine that starts the runtimes; left out or `0` = the machine's budget applies. Budgets are per project or per machine, never per Google account. |
| `autoStopIdleMinutes` | Idle minutes before a panel stops a runtime of this project; `0` = never. |

`up` records the guardrails in force and their source in the runtime's `session.json`, so a panel on
another machine can show them. Commit the file to share the limits; gitignore it to keep them personal.
